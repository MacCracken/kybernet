# kybernet P(-1) audit — 2026-08-24

**Cut at:** v1.4.2
**Predecessor audit:** v1.1.5 — [`2026-05-11-audit.md`](2026-05-11-audit.md)
**Scope:** every `src/main.cyr` + `src/lib/*.cyr` file at the 1.4.1 tree, plus
`src/test.cyr`, `src/bench.cyr`, `qemu/boot-test.sh` and `scripts/bench-history.sh`
**Method:** eight independent audit lenses over the full source (PID-1 lifecycle,
memory safety, syscall/arch portability, privilege & sandboxing, resource
lifetime, edge-boot trust chain, correctness/parsing, optimization), with every
finding adversarially verified by a separate pass instructed to refute it.
**Trigger:** first audit since 1.1.5; three toolchain generations and a full
dependency refresh have landed since (cyrius 6.2.11 → 6.5.35).

## Summary

| Severity | Found | Closed in 1.4.2 | Deferred |
|---|---:|---:|---:|
| CRITICAL | 2 | 2 | 0 |
| HIGH | 5 | 4 | 1 |
| MEDIUM | 7 | 7 | 0 |

| **Total** | **20** | **19** | **1** |

39 candidate findings were filed by the sweep; **13 were refuted** on
verification and are listed at the end so they are not re-filed. The one
deferred item (HIGH-1) is blocked on an upstream argonaut capability, not on
effort.

Two themes dominate this audit, and both are about **gate blindness** rather
than about code that looks wrong:

1. **Nothing in the release gates had ever executed the event loop.** The QEMU
   harness passes `kybernet.harness=1`, which shuts down at phase 9 *before*
   entering the reactor. CRITICAL-1 lives entirely past that point, which is how
   a 100%-CPU spin in PID 1 survived four audits. Fixed structurally: a second
   `kybernet.harness=loop` gate now runs the real loop and asserts a bounded
   wakeup count. It was verified to fail on the unfixed tree.
2. **The advertised security stack is not wired up.** 686 lines of seccomp,
   Landlock and privilege-dropping code — 26 % of kybernet's source — are called
   from no production path (HIGH-1). Several of this audit's findings are defects
   *inside* that code; they are real, but latent until it is enabled.

The 1.1.5 audit's standing-rules list did its job: rules 1, 2, 3 and 5 produced
no new violations in kybernet's own hand-written code. The two CRITICALs came
from classes the list did not cover — kernel **struct layout** as an
arch-dependent quantity (rule 1's sibling), and **epoll readiness semantics**.
Both are added to the checklist.

## CRITICAL-1 — health/watchdog timerfds are never drained: PID 1 spins at 100 % CPU, then panics the kernel

**Class:** level-triggered readiness never cleared
**Site:** `src/lib/eventloop.cyr` (registration) + `src/main.cyr` (handlers)
**Found by:** 5 of 8 lenses independently; confirmed by 5 independent verifications

`timer_new()` arms a repeating timerfd and `epoll_add_read()` registers it with
`epoll_event_new(EPOLLIN, token)` — plain `EPOLLIN`, no `EPOLLET`, so
**level-triggered**. A timerfd stays readable until its 8-byte expiration counter
is `read()`. But the fds were consumed inline as call arguments:

```cyrius
epoll_add_read(epfd, result_unwrap(hfd_r), TOKEN_HEALTH);
```

and bound to nothing. `grep -rn timerfd_drain src/` returned zero hits, and
neither `handle_health_tick` nor `handle_watchdog_tick` touched any fd — so
nothing in the tree *could* drain them.

**Trigger:** every non-harness boot, ~10 s in. `main.cyr` calls
`eventloop_setup(g_sfd, 30, 10)`, so the watchdog timerfd expires first, goes
permanently readable, and `epoll_wait` returns immediately on every subsequent
call for the life of the system. No config, service, or operator action needed.

**Consequence — measured, not argued.** A verification agent built a binary
mirroring the real loop against the real `eventloop.cyr` and ran it: **1,019,588
iterations, 1,019,588 events delivered (`epoll_wait` never blocked once), and
269,171,480 bytes of heap consumed — in 3 seconds.** That is ~90 MB/s of
unreclaimable bump-arena growth on top of a pinned core. PID 1 is exempt from
the OOM killer, so the kernel kills every *other* process first; when
`_linux_new_chunk`'s mmap finally fails, `alloc()` returns 0 and the next
`store64` writes to address 0 → SIGSEGV in PID 1 → **"Attempted to kill init!"**.
With any `HC_COMMAND` health check configured it is also a fork bomb at loop rate.

**Fix.** Retain both timer fds in BSS; drain them via the stdlib's arch-neutral
`timerfd_drain()` as the **first** statement of each handler, ahead of the
`g_init == 0` guard — a drain placed after that early return would still spin.

**Verification.** Reproduced and closed in three places:
- `test_timerfd_drain_clears_readiness` (`src/test.cyr`) asserts the undrained fd
  *stays* ready (proving the test exercises the real condition) and that a drain
  clears it.
- The new `kybernet.harness=loop` QEMU gate reports **21 wakeups** in 5 s against
  a ceiling of 500.
- With the drains commented out, that gate **fails**, and the VM reproduces the
  predicted end state: `FAIL: reactor gate produced no wakeup count` followed by
  `FAIL: kernel panicked in reactor mode`.

## CRITICAL-2 — `struct epoll_event` layout hardcoded to x86_64

**Class:** silent arch portability failure (the 1.1.5 CRITICAL-1..7 class, applied
to struct layout rather than syscall number)
**Site:** `src/lib/eventloop.cyr` — `epoll_wait_events`

x86_64 is the only architecture that marks `struct epoll_event`
`__attribute__((packed))`: `u32 events` at +0, `u64 data` at **+4**, sizeof **12**.
aarch64 uses the natural layout: `u32 events` at +0, 4 bytes padding, `u64 data`
at **+8**, sizeof **16**. kybernet hardcoded the x86_64 numbers:

```cyrius
var events_buf = alloc(maxevents * 12);
store64(ev, load64(events_buf + ei * 12 + 4));
```

The cyrius stdlib **already dispatches on this** when *building* an event —
`syscalls_x86_64_linux.cyr` stores data at +4, `syscalls_aarch64_linux.cyr` at +8
— so the read side was provably inconsistent with the write side.

**Consequence on aarch64** (kybernet ships an aarch64 binary): the kernel fills
`8 × 16 = 128` bytes into a `96`-byte buffer — a **32-byte heap overflow written
by the kernel** — and every token is decoded from the wrong offset, so all events
fall to the `default` arm ("unknown epoll token"). SIGCHLD and SIGTERM are never
processed: no reaping (PID exhaustion) and no shutdown. PID 1 is functionally
dead while appearing to run.

**Fix.** `#ifdef CYRIUS_ARCH_*`-gated `EPOLL_EVENT_SIZE` / `EPOLL_EVENT_DATA_OFF`,
matching the notify.cyr precedent, applied to both the allocation and the parse.

## HIGH-1 — the advertised security stack is applied to nothing *(DEFERRED — blocked upstream)*

`src/lib/seccomp.cyr` (206 lines), `src/lib/sandbox.cyr` (305) and
`src/lib/privdrop.cyr` (175) — **686 lines, ~26 % of kybernet's source** — are
referenced from `src/test.cyr` and `src/bench.cyr` only. `grep` for every entry
point (`seccomp_apply*`, `sandbox_*`, `secure_pre_exec`, `drop_capabilities`,
`set_no_new_privs`) across `main.cyr` and the other `lib/` modules returns
nothing.

Meanwhile README.md advertised *"Security stack — seccomp BPF filters, Landlock
filesystem sandbox, capability dropping, no_new_privs"* and CLAUDE.md listed
"security enforcement" as a delivered goal.

**Why it cannot simply be wired up.** seccomp and Landlock must be installed in
the child between `fork` and `exec`. kybernet delegates spawning to argonaut's
`init_start_service()`, which forks and execs internally, and argonaut exposes
**no pre_exec hook** (`grep -n 'pre_exec\|hook'` across the imported modules
returns nothing). There is no seam for kybernet to run code in the child.

**Disposition.** Not source-fixable in this repo. 1.4.2 corrects the
documentation in both README.md and CLAUDE.md to state plainly that these modules
are built and tested but not applied, and the roadmap carries the upstream ask.
The defects found *inside* this code (HIGH-3, HIGH-4, HIGH-5, MEDIUM-1) are fixed
now so the module is correct whenever the hook lands.

## HIGH-2 — edge-boot gate fell through to a full boot after a failed trust prerequisite

**Site:** `src/main.cyr` phase 6c

`edge_boot_run()` is correctly fail-closed *internally* — it returns 0 when
`tpm_attestation` is required and no TPM is present, or `readonly_rootfs` is
required and dm-verity is unsupported. The **caller** was not:

```cyrius
if (edge_ok == 0) {
    klog("FATAL: edge-boot prerequisite missing — emergency shell");
    drop_to_emergency();
}
# ... falls through to phase 7 (boot stages) and phase 8 (start services)
```

`drop_to_emergency()` **returns** when the shell exits. So on a device that
demanded TPM attestation, removing the TPM produced: a FATAL log, a root
recovery shell, and then a completely normal boot of every service — the exact
outcome verified boot exists to prevent.

**Fix.** The operator still gets the recovery shell; when it exits, kybernet
powers off instead of continuing. Deliberately contrasted with phase 7, where
continuing after a failed *boot stage* is an availability decision about ordinary
services, not a trust decision about the rootfs.

## HIGH-3 — seccomp filter had no architecture check (ABI-switch bypass)

**Site:** `src/lib/seccomp.cyr` — `seccomp_build`

The generated BPF loaded `seccomp_data.nr` as instruction 0 and never examined
`seccomp_data.arch`. Syscall numbers are per-ABI: x86_64 nr 11 is `munmap`, i386
nr 11 is `execve`. A process that switches ABI — `int 0x80` for i386, or the x32
ABI — is matched against an allowlist built for different numbering. This is the
textbook seccomp bypass, and the reason the kernel documentation leads with it.

**Fix.** The filter now emits `LD arch` / `JEQ AUDIT_ARCH → else KILL` / `LD nr`
ahead of the allowlist, with `SECCOMP_AUDIT_ARCH` `#ifdef`-selected per arch.
Regression-tested: `test_seccomp_builder` asserts insn0 loads offset 4, insn1
pins this build's `AUDIT_ARCH` with a `jf` that skips the whole allowlist, and
insn2 loads offset 0.

## HIGH-4 — seccomp jump offsets silently truncated past 254 syscalls

**Site:** `src/lib/seccomp.cyr` — `seccomp_build`

BPF `jt`/`jf` are **u8**. The widest jump this layout emits scales with the
allowlist length, but the only guard was `num + 3 > BPF_MAXINSNS` (4096), so any
filter with more than ~254 entries had its offsets truncated by `store8` and
jumped to arbitrary instructions — allowing or killing the wrong syscalls with no
diagnostic.

**Fix.** `SECCOMP_MAX_ALLOW = 254`; `seccomp_build` returns `Err(EINVAL)` beyond
it. Regression-tested at the boundary in both directions (254 builds, 255 is
rejected).

## HIGH-5 — `seccomp_basic_service()` hardcoded x86_64 syscall numbers

**Site:** `src/lib/seccomp.cyr`

A flat table of x86_64 numbers with no arch dispatch. On aarch64 those numbers
name unrelated calls (x86_64 `read`=0 is `io_setup`; `write`=1 is `io_destroy`),
so the filter would allow a semantically random set while denying `read`/`write`/
`exit` — killing every sandboxed service on its first `read()` — and permit calls
nobody intended. Standing rule 1 applied to a data table rather than a call site.

**Fix.** Per-arch `BasicSyscalls` enum. Every value the cyrius stdlib also
exports was cross-checked against it. ABI differences are handled, not just
renumbering: aarch64 has no `dup2` (only `dup3`), no `arch_prctl` (the entry is
`#ifdef`-ed out), and `epoll_pwait` rather than `epoll_wait`. The eight values
the stdlib does not export (`mprotect`, `rt_sigreturn`, `accept`, `sendto`,
`sigaltstack`, `clock_gettime`, `set_robust_list`, `rseq`) come from the
asm-generic table and are flagged in-source as **pending validation on real
aarch64 hardware** — which gates enabling the module, not this release.

## MEDIUM-1 — `drop_capabilities()` dropped only the bounding set

**Site:** `src/lib/privdrop.cyr`

`PR_CAPBSET_DROP` removes a capability from the **bounding** set, which bounds
what a process can *regain* via file capabilities on exec. It takes away nothing
the process currently holds. A root process that drops its entire bounding set
still has `CAP_SYS_ADMIN` effective.

So `secure_pre_exec(0, 0, 0)` returned `Ok` while leaving the caller **fully
privileged**: bounding set emptied, effective set untouched, and with uid/gid 0
meaning "no change" the `setuid` that would otherwise have cleared the sets never
ran. A security primitive reporting success it did not achieve.

Separately, per-capability `PR_CAPBSET_DROP` failures were counted as
"not dropped" and swallowed — a caller could not distinguish a full drop from a
total no-op.

**Fix.** New `drop_cap_sets()` issues `capset(2)` (`_LINUX_CAPABILITY_VERSION_3`,
per-arch `SYS_CAPSET`) to clear effective/permitted/inheritable, called after the
bounding-set loop (which needs `CAP_SETPCAP` first). Non-`EINVAL` drop failures
now propagate. Marked in-source as unvalidated on privileged hardware — the suite
runs unprivileged, where every path short-circuits on the euid check.

## MEDIUM-2 — TPM PCR read fails open when `tpm2_pcrread` is absent

**Site:** `src/lib/edge_boot.cyr`

`tpm_read_pcr` shells out to `/usr/bin/tpm2_pcrread` via sigil's
`agnosys_run_capture` → `exec_capture`, which returns the captured **byte count**
and discards the child's wait status. A missing or failing binary therefore
surfaces as `Ok(0)`, and sigil zero-fills every unparsed PCR. On a box that asked
for `tpm_attestation`, that is an attestation "pass" derived from a tool that
never ran.

**Fix.** Consumer-side existence check before the call, failing closed. (Upstream
`exec_capture` losing the exit status is worth a sigil filing; kybernet cannot
fix it from here.)

## MEDIUM-3 — service name interpolated raw into the cgroup path

**Site:** `src/lib/cgroup.cyr`

`cgroup_path()` builds `/sys/fs/cgroup/kybernet.slice/{service}` with no
validation, and the result is handed to `mkdir` and to control-file writes. A
name containing `/` or `..` walks out of the slice — `"../../evil"` targets an
arbitrary cgroup directory that kybernet then creates and writes `cgroup.procs`
into. Names come from config, so this needs config-write access to reach, which
is why it is MEDIUM.

This is the same defect argonaut closed at 1.8.6 (its MEDIUM-8,
`sanitize_unit_name`).

**Fix.** `cgroup_name_is_safe()` accepts `[A-Za-z0-9._-]` only and rejects empty,
`.` and `..`; enforced at `create_service_cgroup` and `move_to_cgroup`.

## MEDIUM-4 — emergency shell inherited PID 1's blocked signal mask

**Site:** `src/main.cyr` — `drop_to_emergency`

`setup_signals` blocks SIGCHLD/SIGTERM/SIGINT/SIGHUP/SIGPWR so they can be read
from the signalfd. Blocked masks are inherited across `fork` and **preserved
across `execve`**, and nothing reset it. Ctrl-C was therefore inert in the
recovery shell and in everything launched from it — the one shell where an
operator most needs job control.

**Fix.** `reset_child_signal_mask()` (already linked in via argonaut's
`process_mgmt`) as the first statement of the child branch.

---

## MEDIUM-5 — crash-restarted services escaped their cgroup

**Site:** `src/main.cyr` — `handle_sigchld`

`init_restart_service()` is synchronous and returns a live PID; the return value
was discarded. `start_services()` places a new service into its cgroup, but the
restart path did not — so the first crash-restart silently escaped the cgroup for
the rest of uptime: no memory or CPU limit, and `cgroup.kill` at shutdown misses
it.

**Fix.** Capture the PID; `create_service_cgroup` + `move_to_cgroup` on success,
log on failure.

---

## MEDIUM-6 — `slog()` performed no JSON escaping

**Site:** `src/lib/log.cyr`

Values were interpolated raw into `{"level":"…","msg":"…"}`. A service name
containing a quote, backslash or newline produced malformed JSON and let
attacker-influenced names forge log fields. Service names reach `slog` from
config via `handle_health_tick` / `handle_watchdog_tick`, so this was reachable
log injection.

**Fix.** `_slog_esc()` escapes `"`, `\`, newline, CR, tab and emits `\u00XX` for
other control bytes, with the 6-byte worst case reflected in the buffer guard.

---

## MEDIUM-7 — unbounded arena growth in the reactor and logging hot paths

**Site:** `src/lib/eventloop.cyr`, `src/lib/log.cyr`

The cyrius allocator is a bump arena with no free; when a chunk fills it mmaps a
fresh one. `epoll_wait_events` allocated its raw buffer, a fresh `vec`, and one
16-byte struct per event on **every wakeup**; `klog2` built two `str_builder`s per
call **even when slog was disabled**. In a process that runs for months, both
grow without bound.

**Fix.** The reactor's scratch (raw buffer, event slots) moved to BSS, and its
result vec is reused via `vec_truncate`, which preserves capacity — the stdlib's
documented bounded-memory reset primitive. The structured-log line is built in a
static buffer with no allocation at all, and `klog2` skips it entirely when
`g_log_fd <= 0`. Measured: `epoll_wait(timeout=0)` **365 → 302 ns/op (−17 %)**.

## Refuted on verification (recorded so they are not re-filed)

Thirteen candidate findings did not survive. The instructive ones:

- **`handled_signals` declared `[1]` but storing 8-byte values** (filed 3×) —
  refuted: the array holds byte-sized signal numbers, and the declared size is
  correct for its actual use.
- **`seccomp_from_profile` passes `scrule_names()` entries as syscall numbers** —
  refuted: despite the field name, every in-tree producer (`src/test.cyr`,
  `src/bench.cyr`) pushes raw numbers, so the consumer is consistent. Worth a
  naming note upstream, not a defect here.
- **`readonly_rootfs` never enforced / empty `pcr_bindings` skips attestation** —
  refuted as *defects*: both are honestly documented deferrals to 1.2.1, stated
  in-source.
- **`is_mounted` off-by-one read**, **tmpfiles Str-as-cstr**, **notify arena
  leak**, **`cgroup.kill` write unchecked**, **`sandbox_from_config` bare return**
  — each refuted against the actual code.
- **`boot-stage desc` raw `Str` to `klog2`** — filed, and genuinely real at the
  1.4.1 tree (`main.cyr:412`/`:416` passed the boxed `Str` while the success path
  used `str_data`), but refuted by the verifier because it had **already been
  fixed** in the working tree by the time verification ran. Recorded as fixed, not
  as refuted: `strlen` on a `Str` box walks the pointer field, and the failure
  arms are exactly where an operator needs the stage name.

## Standing rules added to the kybernet audit checklist

Appended to CLAUDE.md alongside the 1.1.5 rules:

1. **Kernel struct *layout* is as arch-specific as the syscall number.**
   `struct epoll_event` is packed on x86_64 (stride 12, data +4) and natural
   everywhere else (stride 16, data +8). Any code that parses a kernel struct
   by hand needs the same `#ifdef CYRIUS_ARCH_*` treatment rule 1 demands for
   syscall numbers — and must agree with whatever the stdlib does on the write
   side.
2. **Every level-triggered epoll registration needs a drain.** A timerfd,
   signalfd or eventfd stays readable until its counter is read. Register the
   fd, retain the fd, drain it in the handler *before* any early return.
3. **A release gate that stops before the event loop does not test the event
   loop.** `kybernet.harness=loop` must stay green and stay in CI; if a future
   change makes the reactor gate awkward, fix the change, not the gate.

## Upstream filings adjacent to this audit

- **argonaut — pre_exec hook.** Without a seam to run code in the child between
  fork and exec, kybernet cannot apply seccomp/Landlock/capability drops to
  services (HIGH-1). This is the single blocker on ~26 % of kybernet's source
  becoming live.
- **sigil — `exec_capture` discards the child's exit status**, so
  `tpm_read_pcr` cannot distinguish "tool missing" from "tool returned nothing"
  (MEDIUM-2). Worked around consumer-side here.
